# ADR-0001 — Model-first, with migration-mediated DDL

**Status:** Proposed · 2026-08-23
**Supersedes:** the database-first position of this ADR's first draft.

## Context

Three families exist:

- **Model-first** (Ent, Hibernate, EF Core, Prisma) — schema declared in the
  host language; DDL and query API both derive from it.
- **Database-first** (sqlc, sqlboiler, go-jet) — the database is authoritative;
  code is generated by introspection.
- **Runtime-first** (GORM `AutoMigrate`) — the ORM applies DDL itself.

This ADR originally chose database-first, to avoid the failure mode of an ORM
silently changing a production schema, and to fit the `anubis` rule that SQL
lives only in `db/queries/` and `migrations/`.

**That reasoning conflated two separable concerns:** *where the schema is
declared* and *who applies DDL*. The danger is the second one. Choosing
database-first to avoid it discards the benefits of the first for no gain.

Two requirements added after the first draft make the original choice untenable:

1. **MongoDB is a target.** A document store has no schema to introspect.
   Database-first is not merely worse for Mongo — it is impossible.
2. **MySQL, MariaDB, SQL Server, and Oracle are targets.** Database-first across
   five engines means five sets of migrations kept semantically identical by
   hand. That has never worked anywhere.

## Decision

**The Go model is the source of truth, and it is a plain struct** — not a DSL.
Nullability, foreign keys, has-many, many-to-many, enums and typed `jsonb` are
all derived from the Go types. **There are no struct tags**: per-column settings
go through `t.Col(&u.Email).Unique().Size(320)` in an optional
`Schema(t *raorm.Table)` method, where every field reference is a *field
pointer* — so a rename is a compile error, not a silent stale string. Struct-as-model and
codegen are orthogonal — the generator reads the struct at build time, so a
simpler declaration costs the compilation thesis nothing.

raorm generates both the query API and a **migration file** from it.

**raorm never applies DDL.** The generator emits a numbered, forward-only,
reviewable `.sql` (or per-target equivalent) into `migrations/`. Your existing
migration runner applies it. There is no `AutoMigrate`, no runtime DDL, no
library code path that can alter a schema.

**Introspection remains a first-class front end.** `raorm import` generates the
model from an existing database — the adoption path for `anubis` and for any
schema raorm did not create. Database-first is demoted from *default* to
*on-ramp*, not deleted.

Drift is caught by verification, not by making the database authoritative:

| Command | Compares | Fails when |
|---|---|---|
| `raorm verify --stale` | generated code ↔ model | regeneration would change output |
| `raorm verify --drift` | model ↔ live database | production differs from the model |
| `raorm verify --pending` | model ↔ `migrations/` | the model changed and no migration was generated |

`--pending` is the load-bearing one: *"you changed the model and did not
generate a migration"* becomes a CI failure rather than a deployment surprise.

## Consequences

**Good.** One canonical schema across all targets — the only workable answer for
five SQL dialects plus Mongo. Portability constraints become declare-time errors
(Oracle's 30-char identifiers and empty-string-is-NULL, absent native `BOOLEAN`,
`NUMBER` precision mapping) instead of discoveries on a customer install. The Go
type system carries enums, value types, and per-dialect overrides that SQL
comments would have to encode. Renames are one edit, not a two-step dance
through a state that does not compile. Schema and fetch plans live in the same
language.

**Bad.** raorm now owns a schema-diff engine — the subsystem the first draft was
pleased to avoid. Scope grows; a bad diff can emit a bad migration.

**Mitigations.** Migrations are ordinary reviewed files, not applied artifacts.
Destructive steps (drop column, narrow type, drop index) require an explicit
`--allow-destructive` and are annotated in the emitted SQL. Diff output is
byte-deterministic so it can be golden-tested. Delegating to Atlas instead of
hand-rolling the differ is an open option and is preferred if it fits the
multi-dialect and Mongo requirements.

**A rule change for `anubis`, stated plainly.** Today SQL lives only in
`db/queries/` and `migrations/`. Under this ADR, schema *shape* is declared in
Go. The intent survives — DDL still lands in `migrations/`, forward-only and
reviewed — but it is generated rather than hand-written. Adopt this ADR and that
`anubis` rule must be reworded. It is a deliberate change, not an oversight.

**Reversible?** Partly. The schema IR has three front ends (model, introspection,
migration files) and one back end. Reverting to database-first means demoting
the model front end, not restructuring. The migration *emitter* would be the
sunk cost.
